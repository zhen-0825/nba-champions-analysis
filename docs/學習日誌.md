### 【今天的技術原理】SQL 建表與資料型態

**比喻**：建表像設計一張「Excel 表格的表頭，而且每一欄都規定只能填什麼」。Excel 裡你可以在「日期」欄打「明天」，資料庫不行——欄位一開始就說好是日期，就只能放日期。好處是：資料一定整齊，算平均、排日期時不會出錯。

專案的 schema.sql（你第一次在 Supabase SQL Editor 跑的那份）：

```sql
create table if not exists games (
  game_id     text primary key,         -- NBA 官方比賽編號，例如 0022500123
  game_date   date not null,            -- 比賽日期
  season      text not null,            -- 球季，例如 2025-26
  season_type text not null             -- Regular Season / PlayIn / Playoffs
);
```
- `create table if not exists games`：建立一張叫 games 的表；「如果已經有了就跳過」，所以整份 SQL 重跑也不會出錯。
- `game_id text`：比賽編號用**文字**不用數字，因為開頭的 `00` 很重要。存成數字的話 `0022500123` 會變成 `22500123`，就對不上 NBA 的編號了。
- `primary key`：這一欄是每一列的「身分證字號」，不能重複、不能空白（明天的主題）。
- `game_date date`：**日期**型態。這樣才能算「和前一場差幾天」（賽程與休息頁），也能依日期正確排序。
- `not null`：這一欄一定要填。
- `season text`：「2021-22」中間有 `-`，不是數字，所以用文字。

```sql
create table if not exists player_game_stats (
  ...
  team_id    bigint references teams(team_id),
  min        numeric(5,2),             -- 上場時間（分鐘）
  pts        int,                      -- 得分
  ...
);
create table if not exists team_games (
  ...
  is_home boolean,                      -- 是否為主場
```
- `bigint`：很大的整數。球隊編號像 `1610612744` 超過 21 億，一般 `int`（最大約 21 億）放不下，所以用 bigint。
- `int`：一般整數，得分、籃板這種不會有小數的。
- `numeric(5,2)`：精確的小數，總共 5 位數、其中 2 位在小數點後面，所以最大 `999.99`。上場時間會有 `34.52` 分鐘這種小數。
- `boolean`：只有 true／false（是／否）。主場與客場頁的 `filter (where tg.is_home)` 就是直接拿它當條件。
- `references teams(team_id)`：這個 team_id 一定要在 teams 表裡找得到（外鍵，明天講）。

| 型態 | 放什麼 | 專案例子 |
|---|---|---|
| text | 文字 | game_id、season、matchup |
| int／bigint | 整數 | pts、team_id |
| numeric(p,s) | 精確小數 | min、off_rating |
| date | 日期 | game_date |
| boolean | 是／否 | is_home、made（投籃有沒有進） |

小提醒：網站從資料庫讀回來時，numeric 有時會變成「文字」，所以 app.py 很多地方先寫 `pd.to_numeric(..., errors="coerce")` 轉成數字（10/29 學過）。今天新寫的 `playoff_stars()` 第一步也是這樣。

### 【今天新功能的程式拆解】

```python
def playoff_stars(players, n_star=3, min_reg=40, min_po=4):
    d = players[players["season_type"].isin(["Regular Season", "Playoffs"])].copy()
    for c in ["gp", "min", "pts", "fga", "fta"]:
        d[c] = pd.to_numeric(d[c], errors="coerce")
    d = d[d["gp"] > 0]
    d["ppg"] = d["pts"] / d["gp"]
    d["mpg"] = d["min"] / d["gp"]
    d["ts"] = d["pts"] / (2 * (d["fga"] + 0.44 * d["fta"])).where(lambda x: x > 0)
    d["p36"] = d["pts"] / d["min"].where(d["min"] > 0) * 36
    keys = ["season", "team_id", "abbreviation", "player_id", "player_name"]
    reg = d[(d["season_type"] == "Regular Season") & (d["gp"] >= min_reg)].copy()
    reg["rk"] = reg.groupby(["season", "team_id"])["ppg"].rank(ascending=False, method="first")
    reg = reg[reg["rk"] <= n_star]
    po = d[(d["season_type"] == "Playoffs") & (d["gp"] >= min_po)]
    cols = ["gp", "ppg", "mpg", "ts", "p36"]
    m = reg[keys + ["rk"] + cols].merge(po[keys + cols], on=keys, suffixes=("_r", "_p"))
    for c in ["ppg", "mpg", "ts", "p36"]:
        m[f"d_{c}"] = m[f"{c}_p"] - m[f"{c}_r"]
```
- 第 1 行：參數都有預設值（10/30 學的函式與參數）：前 3 名、例行賽至少 40 場、季後賽至少 4 場。想改成「前 2 名」只要呼叫 `playoff_stars(player_raw, n_star=2)`。
- 第 2 行：只留例行賽和季後賽（附加賽不算）。`.copy()` 免得改到快取裡的原始資料。
- 第 3～4 行：今天的主題——資料庫傳回的數字可能是文字，先轉成數字。
- 第 6～9 行：場均得分、場均分鐘、真實命中率、每 36 分鐘得分。`.where(... > 0)` 是老朋友：分母是 0 時不要除。
- 第 11～13 行：在每一隊每一季裡，依場均得分排名，只留前 3 名＝「球星」。`method="first"` 讓同分時不會有兩個第 1。
- 第 14 行：季後賽至少打 4 場（首輪被橫掃也剛好 4 場）。
- 第 16 行：`merge` 把同一位球員、同一隊、同一季的例行賽和季後賽「並排」。`suffixes=("_r", "_p")`：兩邊都有 ppg，所以改名成 `ppg_r`（regular）和 `ppg_p`（playoffs）。`on=keys` 也包含 team_id，所以季中被交易的球員，只會配到他打季後賽的那一隊。
- 第 17～18 行：季後賽 − 例行賽，正數＝季後賽比較好。

```python
RP["grp"] = RP["champion"].map({True: "冠軍", False: "其他季後賽球隊"})
G = RP.dropna(subset=[f"d_{col}"]).groupby(["star", "grp"])[f"d_{col}"].agg(["mean", "size"])
```
- `.map({True: ..., False: ...})`：用字典把 True／False 換成中文分組名（10/29 字典）。
- `groupby([...]).agg(["mean", "size"])`：每一組算平均變化和人數（10/31 groupby），就是第 2 張長條圖的高度和「幾人」。

```sql
with s as (
  select team_id, abbreviation, season, season_type, player_id, player_name, gp,
         pts::numeric / gp                                   as ppg,
         pts / nullif(2 * (fga + 0.44 * fta), 0)             as ts
  from player_season_stats
  where gp > 0
)
select r.season, r.abbreviation, r.player_name,
       round(r.ppg, 1) as 例行賽得分, round(p.ppg, 1) as 季後賽得分,
       round(r.ts * 100, 1) as 例行賽命中, round(p.ts * 100, 1) as 季後賽命中
from s r
join s p          on p.player_id = r.player_id and p.team_id = r.team_id
                 and p.season = r.season and p.season_type = 'Playoffs'
join champions c  on c.season = r.season and c.team_id = r.team_id
where r.season_type = 'Regular Season' and r.gp >= 40
order by r.season, r.ppg desc;
```
**預期結果**：每個冠軍球季好幾列（有打季後賽的球員），依例行賽得分由高到低，第一列就是那季的頭號球星，數字應該和網站第 3 張表一樣。`pts::numeric` 是今天的主題：把整數轉成小數再除，不然整數 ÷ 整數在 SQL 裡會「無條件捨去」（25 ÷ 2 ＝ 12）。`nullif(x, 0)`：x 是 0 就當成空值，避免除以 0。

### 【今天的技術原理】快取與 data 資料夾

**比喻**：快取像「把常查的答案抄在便利貼上」。第一次要跑去圖書館（NBA 官網或 Supabase）查，查完抄下來貼在桌上；下次有人問同一題，直接看便利貼，不用再跑一趟。但便利貼會過期，所以要寫上「幾分鐘後作廢」。

專案裡有兩種便利貼：

**1. 網站的便利貼：`@st.cache_data`（app.py）**
```python
@st.cache_data(ttl=900, show_spinner="從資料庫讀取資料中…")   # 每 15 分鐘重新讀一次資料庫
def read_stats(name, order_cols):
    ...
```
- `@st.cache_data`：放在函式上面的「裝飾」，意思是「這個函式的結果要記住」。
- `ttl=900`：time to live，900 秒（15 分鐘）後作廢，下次會重新讀資料庫。所以每天 15:30 更新完，最慢 15 分鐘網站就會看到。
- 記憶是**依參數分開**的：`load_shots(勇士, 2021-22, 例行賽)` 和 `load_shots(金塊, 2022-23, 例行賽)` 是兩張不同的便利貼。今天新寫的 `load_team_games_all(team_ids)` 參數是「所有已載入球隊的編號」，明天多 2 隊，參數就不一樣，自然會重新讀。
- 左側「重新讀取最新資料」按鈕做的是 `st.cache_data.clear()`：把所有便利貼撕掉。
- 讀取失敗（丟出錯誤）時 Streamlit 不會記住，所以下一次會再試；但如果函式「吞掉錯誤、回傳空表格」，空表格就會被記住 15 分鐘——這就是為什麼剛建好資料表時，有時要按一下「重新讀取」。

### 【今天的技術原理】函式與參數（命令列參數 --start、--next）

**比喻**：函式像一台「果汁機」，參數是你丟進去的水果。同一台果汁機，丟蘋果出蘋果汁、丟芒果出芒果汁——程式不用改，換參數就好。**命令列參數**則是「在終端機下指令時順便交代的話」，例如 `python load_to_supabase.py --next 2` 的意思是：「執行這支程式，順便告訴它：再加入 2 支球隊。」

專案裡真的在用的幾行（load_to_supabase.py 的 `main()`）：

```python
def main():
    parser = argparse.ArgumentParser(description="把 NBA 數據寫進 Supabase")
    parser.add_argument("--start", default=DEFAULT_START, help="開始日期，格式 2006-10-01")
    parser.add_argument("--next", type=int, metavar="N", help="再加入 N 支還沒載入的球隊")
    parser.add_argument("--progress", action="store_true", help="顯示 30 隊的載入進度")
    args = parser.parse_args()

    if args.progress:
        show_progress()
        return
    if args.next:
        ok = load_next(client, args.next)
```
- `def main():`：定義一個叫 main 的函式（果汁機），還沒開始打，只是把機器組好。
- `argparse.ArgumentParser(...)`：一個「聽指令的櫃台」，負責讀你在終端機打的那串字。
- `add_argument("--start", default=...)`：登記一種指令。沒交代 `--start` 時，就用預設值（2006 年）。
- `type=int`：把 `--next 2` 的 "2"（文字）轉成數字 2，才能拿來算。
- `action="store_true"`：開關型參數，有寫 `--progress` 就是 True，沒寫就是 False，後面不用接值。
- `args = parser.parse_args()`：櫃台開始讀指令，結果放進 `args`，之後用 `args.next`、`args.start` 拿。
- `if args.progress: ... return`：只要看進度，就印完直接結束，不抓資料。
- `load_next(client, args.next)`：呼叫另一個函式，把「要加幾隊」當參數傳進去。


### 【今天的技術原理】變數、串列、字典

**比喻**：
- **變數**像貼了名字的盒子：`pl_team = "GSW"`，之後說 `pl_team` 就是在說 "GSW"。
- **串列（list）** 像一排有順序的置物櫃，用位置（0、1、2…）拿東西：`ALL_TEAMS[0]` 是第一個。
- **字典（dict）** 像通訊錄：用「名字」查「電話」，不用管順序：`TEAM_ZH["GSW"]` 查到 "勇士"。
- **集合（set）** 像點名單：只在乎「有沒有在名單上」，查得非常快。

```python
def prep_playtypes(pt):
    pt = pt.copy()
    for c in ["gp", "poss", "poss_pct", "ppp", "pts"]:
        pt[c] = pd.to_numeric(pt[c], errors="coerce")
    if pt["poss_pct"].max() > 1.5:
        pt["poss_pct"] = pt["poss_pct"] / 100
    pt["side"] = pt["type_grouping"].str.lower()
    keys = ["season", "season_type", "side", "play_type"]
    off = pt["side"] == "offensive"
    pt.loc[off, "rk_ppp"] = pt[off].groupby(keys)["ppp"].rank(ascending=False, method="min")
    pt.loc[~off, "rk_ppp"] = pt[~off].groupby(keys)["ppp"].rank(ascending=True, method="min")
    pt["rk_use"] = pt.groupby(keys)["poss_pct"].rank(ascending=False, method="min")
```
- `pt.copy()`：先複製一份再改，不會動到快取裡的原始資料。
- `pd.to_numeric(..., errors="coerce")`：資料庫傳回來的 numeric 有時是文字，轉成數字；轉不了就變空值，不會當機。
- `if ... > 1.5: / 100`：保險絲。使用率應該是 0～1（例如 0.12＝12%）；萬一存成 12，就自動除以 100。
- `keys = [...]`：「同一季、同一種比賽、同一端、同一種戰術」的 30 支球隊放在一組比較。
- `off = pt["side"] == "offensive"`：一整欄的 True/False，標出哪些列是進攻端。
- `rank(ascending=False)`：進攻端每回合得分越**高**排越前面（第 1 名）。
- `rank(ascending=True)`：防守端是對手的每回合得分，越**低**越好，所以反過來排。
- `pt.loc[~off, ...]`：`~` 是「相反」，也就是防守端那些列。
- `rk_use`：使用率排名，用得越多排越前面。熱力圖的兩種排名就是這兩欄。

**1. 一頁一頁讀投籃紀錄（`load_shots`）**

```python
@st.cache_data(ttl=3600, show_spinner="讀取投籃紀錄中…（一季約 7,000 次出手）")
def load_shots(team_id, season, season_type):
    client = get_client()
    rows, start, page = [], 0, 1000
    try:
        while True:
            part = (client.table("shots")
                    .select("game_id,game_event_id,player_name,loc_x,loc_y,made,zone_basic,zone_area,shot_distance")
                    .eq("team_id", team_id).eq("season", season).eq("season_type", season_type)
                    .order("game_id").order("game_event_id")
                    .range(start, start + page - 1).execute().data)
            rows += part
            if len(part) < page:
                break
            start += page
    except Exception:
        return pd.DataFrame()
    return pd.DataFrame(rows)
```

- `@st.cache_data(ttl=3600, ...)`：讀過一次的結果記住 1 小時，同一隊同一季第二次看就不用再等。
- `rows, start, page = [], 0, 1000`：準備一個空串列裝資料；從第 0 筆開始；每次讀 1000 筆（Supabase 一次最多給 1000 筆）。
- `.select("game_id,...")`：只拿需要的欄位，不用 `*`，傳輸量少很多。
- `.eq("team_id", ...).eq("season", ...)`：**最重要的一行**。shots 有幾十萬筆，一定要先叫資料庫只給「這隊、這季、這種比賽」，不然會讀到天荒地老。
- `.order(...)`：分頁時一定要固定排序，不然第 2 頁可能和第 1 頁重複或漏掉。
- `.range(start, start + page - 1)`：第一次拿第 0～999 筆，第二次 1000～1999 筆……
- `if len(part) < page: break`：這一頁不滿 1000 筆，代表讀完了，跳出迴圈。
- `except Exception: return pd.DataFrame()`：資料表不存在或連線出錯時，回傳空表格，畫面就會顯示「尚未載入資料」而不是一片紅色錯誤。

**2. 把出手整理成「每區一列」（`zone_table` 的核心）**

```python
g = d.groupby(["zone_basic", "zone_area"], as_index=False)[["fga", "fgm"]].sum()
g["fg_pct"] = g["fgm"] / g["fga"].replace(0, pd.NA)
g["share"] = g["fga"] / g["fga"].sum()
g["value"] = g["zone_basic"].map(lambda z: 3 if "3" in z else 2)
g["pps"] = g["fg_pct"] * g["value"]
```

- `groupby([...]).sum()`：把「同一區」的出手加起來，例如「中距離（左翼）」出手 512、命中 205。
- `fg_pct`：命中率 = 命中 ÷ 出手；`.replace(0, pd.NA)` 避免除以 0。
- `share`：這區佔全部出手的比例，就是「每 100 次出手有幾次在這裡」。
- `value`：區域名稱裡有「3」（Corner 3、Above the Break 3）就是三分區，投進值 3 分，其他值 2 分。
- `pps`：每次出手平均得分 = 命中率 × 分值。**這一欄就是今天假設的關鍵**：中距離 45% × 2 = 0.90 分，三分 36% × 3 = 1.08 分。
